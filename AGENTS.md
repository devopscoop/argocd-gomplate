# AGENTS.md

Instructions for AI coding agents working in this repo. `CLAUDE.md` is a symlink
to this file, so this is also the guidance Claude Code (claude.ai/code) reads.
Edit this file; do not replace the symlink with a copy.

## What this repo is

The repo produces exactly one artifact: an Alpine container image carrying
`kubectl`, `helm`, and `gomplate` (plus bash/curl/jq/gettext). It runs as a
sidecar in ArgoCD's repo-server so the gomplate config-management plugin has its
tools available.

There is no application code here. The CMP script that actually calls these
tools lives in the separate `argocd-config` repo, and the ApplicationSet pattern
that consumes the plugin lives in `argocd-applicationset-pattern` (both linked
from README.md). The whole surface of this repo is the `Dockerfile`, the CI that
builds and publishes it, and the host-side package manifests.

Consequence: there is no test suite, no linter, and no build system. "Does it
work" means the image builds for both published architectures and the tools
inside it run.

## Commands

Build for the host architecture:

```shell
docker build -t argocd-gomplate:latest .
```

Build both published architectures (what CI does; requires buildx):

```shell
docker buildx build --platform linux/amd64,linux/arm64 -t argocd-gomplate:latest .
```

Check that the tools landed at their pinned versions — `ENTRYPOINT` is
`/bin/bash`, hence the `-c`:

```shell
docker run --rm argocd-gomplate:latest -c \
  'kubectl version --client && helm version --short && gomplate --version'
```

On macOS the Brewfile installs colima plus the Docker CLI rather than Docker
Desktop, so `colima start` is needed before any build.

## Dockerfile conventions

Tool versions are `ARG`s at the top of the Dockerfile (`GOMPLATE_VERSION`,
`KUBECTL_VERSION`, `HELM_VERSION`). When bumping one, update the "What's in the
Image" list in README.md in the same change — it names versions and otherwise
drifts silently.

Download URLs interpolate `${TARGETARCH}`, which BuildKit and buildx set
automatically. Building with the legacy builder (`DOCKER_BUILDKIT=0`) leaves it
empty and the `curl` steps fetch a malformed URL.

## GitHub Actions

Every `uses:` is pinned to a full commit SHA with a trailing `# vX` version
comment. Preserve that format when adding or bumping an action.

- `build_and_push.yaml` — builds linux/amd64 + linux/arm64. Pushes to
  `ghcr.io/<owner>/<repo>` on main, on `v*` tags, and on manual dispatch;
  pull requests build without pushing. Tags are generated by
  docker/metadata-action (semver from `v*` tags, `latest` on the default
  branch).
- `claude.yml` — responds to `@claude` mentions on issues and PR comments. No
  `--allowed-tools` is set, which deliberately leaves the Bash tool disabled: it
  pushes a work branch and returns a prefilled PR link for a human to submit,
  rather than opening the PR itself.
- `claude-code-review.yml` — automatic review on every PR, running in agent mode
  (it passes a `prompt`). The `--allowed-tools` allowlist there is load-bearing:
  in agent mode it is what registers the inline-comment MCP server, so removing
  it makes the job review the diff and post nothing. The code-review plugin is
  deliberately not used, because claude-code-action has no handling for its
  `ReportFindings` output.

Both Claude workflows pin `--model claude-opus-5 --effort xhigh` so CI does not
drift when the CLI default changes.

## Package manifests

This repo ships a `Brewfile` (macOS: `brew bundle`) and a `pkglist.txt` (Arch Linux) that install every local CLI tool the repo uses. Keep them in sync with the code:

- When you add a tool, script, or a new external command that a human runs on their workstation, add the package to BOTH files, with a comment noting what uses it.
- When a tool stops being used, remove it from both files.
- Tools installed by the Dockerfile (gomplate, kubectl, helm, jq, etc.) run inside the image — they do NOT belong in the manifests. Only host-side tools do.
- Verify package names before adding them: `brew info <formula>` for Homebrew, and the official repos/AUR for Arch. If a package is AUR-only, note that in pkglist.txt's header instructions.
- Update the "Prerequisites" section in README.md if the tool list changes.
